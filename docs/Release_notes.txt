  V1.3.1 (DeepMosaicsPlus)
    New:
      1. Added classical single model training mode to UI tool 
      2. New detail percentage for synthetic clips so that generated clips are given features over gradients. Models are made to recover detail
      3. Textures can be taken from images, and I've added 3 basic ones to start (note: this synthetic generation + buckets are experimental aiming to cut down sourcing material while improving accuracy)
      4. Texture images are kept at up to 2048 px on their longest side.

    Fix:
      1. Fix ResnetGenerator missing forward method
      2. Fix mismatch between training and cleaning modes which messed up bucket sizes
      
  V1.3.0 (DeepMosaicsPlus)
    New:
      1.512px is now the default size for training (--finesize 512, datasets stored at 572px) and for running the video model; a model's recorded size (model_info.json) still wins, and --infer_size / "Model input size" overrides it (use 256 for older models if 512 looks worse)
      2.Faster cleaning: frames are decoded ahead on a background thread, mosaic detection runs a whole batch per GPU call, paste-back and frame encoding use several threads, and on CUDA/ROCm the model's input is resized and normalised on the GPU (--gpu_preprocess); a [timing] line reports where the time went
      3.Optional half precision for the video model on CUDA/ROCm (--fp16 / "Half precision (experimental)")
      4.AMD PyTorch+ROCm (Windows) as a backend: the installer can install and verify it ("rocm"), the device badge shows ROCm, and it is used for both inference and training through the normal GPU path
      5.tools/make_generated_dataset.py: training clips without the ROI detector, either procedural animation ("generated") or random regions of your own clean videos/images ("crops", e.g. for anime). Generated clips come in an anime look and a real-life look (--style) with an adjustable share of beige/pink tones (--skin_tone); the dataset tool has a button for them (step 2b)
      6.Dataset & Training tool redesigned: one Workflow screen with the four steps as cards (settings and a live status line on each), "Run selected steps" chains them (e.g. generate clips, then train), everything is checked before a run starts, progress bar and elapsed time, Stop also stops the training child process, choice of buckets to train, GPU memory estimate against your card. 1 sample per batch takes between 3.6GB to 4GB. If you have 4 samples per batch that should be about 16GB VRAM needed. 
      7.Training reports where its time goes: data= / gpu= per iteration, and a [speed] summary at iterations 20 and 200 with GPU memory use and a warning when memory is full or training waits for data; the dataset tool estimates how long a run will take
      8.Training checks memory before it starts: fewer data-loading processes when system RAM is short ([memory] line), and a warning with a safe batch size when the batch will not fit in GPU memory
      9.Dataset & Training tool: "Training mode" on the Train step. Single model (original, the default) trains one model from the whole synthetic pool and the real pairs of all buckets, with the original wide random mosaic sizes (checkpoints/clean_single; tools/train_all_buckets.py --single). Size buckets (experimental) trains one model per mosaic size as before
      10.Main GUI: "Auto-select model by mosaic size" (--auto_model) picks the bucket model matching the measured mosaic size and shows how many bucket models are installed; a missing bucket uses the nearest installed one. Dataset tool: "Install trained models" copies the newest finished checkpoint and its .json to where the program expects it (each bucket's manifest path, or pretrained_models/clean_single.pth); a replaced model is kept as .previous
      11.Generated clips have detail to restore (--detail, "Detail" in step 3; on by default): multi-scale texture, line art and hair-like strokes, and video-like compression. --textures / "Texture images" fills backgrounds and shapes with patches of your own photos or texture packs. Detail 0 keeps the old smooth look, which mostly teaches the model to smooth blocks over
    
    Fix:
      1.The final encode could start before the last cleaned frames were written (the writer was only waited on for 30 seconds); detection masks are now guaranteed to be on disk before cleaning starts
      2.Caches and temp files no longer go to the system drive: PyTorch downloads, the ROCm kernel cache and temporary files are kept in a folder beside the project (<project>_cache; DMP_CACHE_DIR to choose another)
      3.--continue_train did nothing in train/clean/train.py: every run restarted at iteration 0. It now loads the newest checkpoint (generator, discriminator and optimizer state, saved in resume_state.pth) and continues counting from that iteration, so TensorBoard curves continue too
      4.ResnetGenerator had no forward(), so resnet models (e.g. clean_youknow_resnet_9blocks.pth) failed with "missing the required forward function"
      5.Size buckets measured the mosaic block size against the whole frame, but the clean model sees a crop around the mosaic area resized to its input, so blocks are several times larger to the model when the mosaic area is small. Real pairs landed in too-small buckets (2-3% instead of 4-5%) next to synthetic mosaics of the bucket's real size, and --auto_model picked models trained on much smaller blocks (blocks smoothed, no detail). Sizes are now % of the square the model sees everywhere: --auto_model, bucket_real_pairs.py (measured on the crop each pair is cut to) and --dataset_mosaic_pct (relative to --finesize, with a wider 0.75-1.33x range so neighbouring buckets overlap). Bucket models trained before this should be retrained, and real pairs re-sorted (step 1)

  V1.2.0 (DeepMosaicsPlus)
    New:
      1.Configurable video codec on output encode: h264 / hevc / av1 / vp9 / h264_nvenc / hevc_nvenc
      2.Per-codec default CRF/CQ values (CRF scales differ between encoders)
      3.Modern 3-panel GUI with slider + editable spinbox for CRF, live preview, and seek bar
      4.Clear preflight error when ffmpeg/ffprobe are missing, instead of a bare OS error deep in processing
      5.Traditional (non-AI) mosaic cleaning path, luma/bilateral sharpening, frequency injection post-processing
      6.GIF input support: processed as video, output converted back to a looping GIF with a lossless path (PNG frames + lossless intermediate)
      7.Image and GIF previews in the GUI, with Detection/Cleaned toggle to compare before and after
      8.Inference device badge in the GUI (CUDA / DirectML / CPU), reported by the run itself
      9.DirectML: --gpu_id selects the DirectML device; the cleaning model and image path run on the GPU (previously CPU)
      10.Options that don't apply to images or GIFs are greyed out in the GUI
      11.Frames are kept after a run so the preview can be scrubbed (cleared when the program closes); "Finished" overlay on the last frame
      12.Dataset tool: --save_freq and --scene_accept_ratio settings; video models can clean single images
      13.Installer detects the GPU and installs a working PyTorch build (verified on the GPU); requirements.txt; launchers that use the installer's Python (works with venvs)
      14.GIF inputs can be saved as GIF (default) or MP4 (--gif_to_mp4 / GUI checkbox)
      15.Train and run the video model at other sizes (256/384/512): --finesize (--loadsize is automatic); the size is recorded next to each checkpoint (model_info.json) and read at inference; --infer_size / GUI "Model input size" override it; dataset tool has a model-size selector with memory guidance
      16.Dataset builder reports how large the mosaic crops are in your footage and warns when training would only enlarge them
      17.NVIDIA RTX 50-series (Blackwell) support: startup GPU self-test explains an unusable CUDA build in plain language and falls back to CPU; installer chooses PyTorch builds by GPU generation (Blackwell needs CUDA 12.8+, CUDA 13 builds dropped GTX 10/V100); tools/check_gpu.py diagnoses CUDA problems (driver, build, torchvision mismatch)
      18.Image results can be saved as JPG / PNG / WebP / BMP / TIFF (--img_format, default: same as the input), with --img_quality, --png_compression, --webp_lossless; PNG and WebP keep transparency, other formats fill it with --img_background; settings appear in the GUI for image inputs; WebP and TIFF inputs are now recognised
    Fix:
      1.--encode_crf was defined but never actually passed to the video encoder; now wired through correctly
      2.Frame extraction dropped or duplicated frames at segment boundaries (short clips lost up to ~20% of frames)
      3.Cleaning images near the frame edge produced zoomed/distorted output; "No edge feathering" replaced the whole region instead of only the mosaic
      4.Installer installed CPU-only PyTorch for NVIDIA GPUs on Windows; GUI launched deepmosaic.py with whichever Python was first on PATH (could silently run on CPU)
      5.DirectML: video model failed (Conv3d, inference tensors) and produced noisy output (DirectML's bilinear upsample); both replaced with exact equivalents
      6.Hardware video decode crashed on systems where the decoder isn't usable; now falls back to software
      7.Videos with no audio track crashed; GIF/image runs no longer require ffmpeg
      8.Windows: startup work was repeated in every frame-extraction worker (log spam, slow extraction)
      9.Log no longer jumps to the bottom while scrolled up; missing preview during frame extraction
      10.Files with brackets or non-ASCII characters in the name: GIF results were left as MP4, and the real error was hidden behind "generator didn't stop after throw()"
      11.Videos are encoded as standard yuv420p (widely playable); previously 4:4:4 for PNG frames or full-range yuvj420p for JPEG frames
      12.Real pairs were stored as full frames instead of crops around the mosaic (wrong block scale for training, and random crops often missed the mosaic); tools/bucket_real_pairs.py now crops pairs to the mosaic region (--outsize, --no_crop to keep old behaviour)
      13.Modern GUI failed to start on Python 3.11 and older (SyntaxError: backslash inside an f-string, only allowed on 3.12+); all code now compiles on Python 3.8-3.12
      14.Image results were always saved as JPG, so transparency in PNG/WebP inputs was lost
